## Три обязательных компонента

### 1. Python-агент

- `ThreadingHTTPServer` на порту из `config.json`.
- Эндпоинты: `/ping`, `/health`, `/write`, `/read`, `/list`,
  `/mkdir`, `/delete`, `/hash`, `/run`, `/sandbox`, `/notify`.
- Все файловые пути ограничены корнем установки через `safe_path`.
- Авторизация: заголовок `X-Token` со значением из `.agent_token`.
- Каждый запрос обрабатывается в отдельном потоке; долгий `run` не
  блокирует остальные.

### 2. Chrome-расширение

- **`content.js`** — следит за DOM чата. Находит блоки-команды,
  извлекает id/op/path/тело, шлёт в background.
- **`background.js`** — ведёт ledger отправленных id, обеспечивает
  идемпотентность, пингует агента, ставит на паузу при трёх
  неудачных heartbeat подряд.
- **`sidepanel`** — светофор состояния (агент, content, lastId),
  ledger последних команд, кнопки Self-test и Sandbox-test,
  кнопка «Сброс» для ручного сброса застрявшей очереди.
- Тайминги: cooldown между командами 5s, окно склейки (coalesce)
  2.5s, silence-timer 120s.

### 3. Песочница

Скрипты управления и восстановления:

- `pwlib.py` — обёртка над Playwright (headless-браузер для
  тестов).
- `watchdog.py` — health-монитор агента с файлом `ALERT.json`.
- `recovery_loop.py` — цикл автоподъёма при падении.
- `bridge_kick.py` — отправка текста в чат через CDP.
- `reload_chat.py`, `reload_extension.py`, `reload_panel.py` —
  перезагрузка вкладок и расширения.
- `ping_all.py` — проверка живости всех агентов.
- `read_panel_state.py` — снимок состояния сайдпанели по CDP-порту.
- `doh.py`, `doh_proxy.py` — обход DNS-фильтра через DoH.

## Опциональный мейнфрейм

Когда каналов больше одного, полезно место, где сходится текстовая
информация от всех агентов и телеметрия. Это `sandbox/council_chat/`
— локальный веб-сервер на `:8770`.

Что он даёт:

- **Общий чат.** Все каналы и оператор пишут в один поток
  (`chat.jsonl`).
- **Персональные чаты.** У каждого канала своя лента
  (`chat_<CH>.jsonl`) и ACL: писать в неё может оператор или сам
  канал.
- **Мнемосхема.** Визуальная карта каналов: `lastId`, ping,
  позиция в диапазоне, состояние watchdog/recovery, живые линки
  между агентами.
- **Телеметрия.** `GET /api/status` отдаёт состояние всех
  каналов: `agent_ping`, `lastId`, `cmds_from_start`, `risk`,
  `svc_watchdog`, `svc_recovery`, `svc_params`, `links`.
- **Матрица живости.** `GET /api/health` — параллельная проверка
  всех панелей, агентов и сервисов, плюс алерты.
- **Управление совещанием.** `POST /api/meeting` (HALT/RESUME),
  `POST /api/pause_all` (пишет только оператор), `POST /api/svc`
  (старт/стоп персональных сторожей).

Мейнфрейм не обязателен для работы моста. Один канал может жить
без него. Он нужен, когда каналов несколько и важно видеть картину
целиком.

## 1–10 каналов

`install.py` поддерживает от 1 до 10 независимых каналов. Каждый
канал — это:

- свой `agent.py` на своём порту (`agent_port_base + i`);
- свой CDP-порт (`cdp_port_base + i`);
- свой профиль Chrome (`chrome-<L>-data/`);
- свой префикс id (`AAAA`, `BBAA`, `CCAA`, …).

Каналы изолированы: панель расширения в каждом профиле принимает
только свой префикс. Один канал не «съест» id другого.

Раскладка хранится в `config.json`, создаётся установщиком.
Скрипты:

- `launchers/start-<L>.ps1` — один канал (Chrome + агент).
- `launchers/boot-all.ps1` — **все** каналы + DoH-прокси + сервер
  чата. Читает `config.json`, работает при N от 1 до 10.
- `launchers/stop-all.ps1` — остановить всё.

Все процессы поднимаются через `pythonw` (`-WindowStyle Hidden`)
— без окон на экране.

## Прокси и браузер агента

### DoH-прокси

Если системный DNS недоступен или фильтруется провайдером, Chrome
не открывает внешние сайты. Решение — локальный DoH-прокси:

- `sandbox/doh_proxy.py` слушает `127.0.0.1:9999`.
- Резолвит имена через `8.8.8.8` и `1.1.1.1` (DNS-over-HTTPS).
- Кэширует ответы, устанавливает TCP-соединение напрямую.
- Chrome запускается с флагом `--proxy-server=127.0.0.1:9999`.

### Агент и его браузер

Агент умеет работать в том же браузере, в котором открыт его чат.
Механика — Playwright подключается к Chrome по CDP-порту
(`p.chromium.connect_over_cdp("http://127.0.0.1:<CDP>")`).

Это даёт:

- **Тот же профиль.** Логины, куки, открытые сессии — всё доступно.
  Не нужно заново авторизовываться.
- **Работа с вкладками.** Переход по URL, открытие новых вкладок,
  F5, снятие скриншотов, чтение текста, клики.
- **Вставка текста в чат.** `bridge_kick.py` находит textarea и
  аккуратно вводит сообщение — не ломая черновик (при непустой
  textarea отказывается).
- **Автоматизация браузерных сценариев.** Рецепты из
  `sandbox/web_agent_*.py` — последовательность действий JSON-ом.

Так агент «пользуется своим браузером»: тем же окном, где идёт
диалог. Это позволяет, например, агенту читать статью в другой
вкладке и использовать это в ответе.

## Конфигурация

`config.json` создаётся установщиком и описывает:

- `root` — абсолютный путь установки;
- `n_agents` — число каналов (1–10);
- `letters` — буквы каналов: `["A", "B", ...]`;
- `agent_port_base` — базовый порт агентов (по умолчанию 8760);
- `cdp_port_base` — базовый CDP-порт (по умолчанию 9220);
- `chat_port` — порт сервера чата (по умолчанию 8770);
- `proxy_port` — порт DoH-прокси (по умолчанию 9999);
- `extension` — имя папки расширения (по умолчанию `extension`);
- `bind` — интерфейс сервера чата (`127.0.0.1` или `0.0.0.0`);
- `channels` — карта каналов: `{ "A": {"agent": 8760,
  "cdp": 9220, "prefix": "AAAA"}, ... }`.

Все скрипты читают эти параметры. Никаких хардкодов путей.

## Протокол команд

Описание — в `PROTOCOL.md`. Кратко: блок из трёх решёток с
маркерами BEGIN / CONTENT / END, заголовки id/op/path, тело после
разделителя. Отчёт заканчивается `next_id`.

## Безопасность

- Агент работает только внутри корневой папки установки.
- Токен `.agent_token` не коммитится, не публикуется, не выводится
  в чат.
- Опасные операции (`delete`, деструктивный `run`) можно требовать
  подтверждать в панели — настраивается в sidepanel.
- Chrome-профили и логи — локальные, в git не попадают
  (`.gitignore`).

## Сеть

- Все компоненты слушают `127.0.0.1` по умолчанию.
- Внешние запросы Chrome — через локальный DoH-прокси на `:9999`,
  чтобы обходить DNS-фильтрацию провайдера.
- **Bind сервера чата.** В `config.json` есть поле `bind`:
  - `"127.0.0.1"` (по умолчанию) — сервер виден только с этой
    машины;
  - `"0.0.0.0"` — доступен из локальной сети по имени машины или
    по её IP.
  При `bind: 0.0.0.0` сервер чата открывается в локальной сети.
  Остальные компоненты (агенты, CDP) остаются только на
  `127.0.0.1`.

## Фоновые процессы

Все python-процессы (агенты, doh_proxy, сервер чата) запускаются
через `pythonw.exe` + `-WindowStyle Hidden` — окна консоли на
экране не появляются. Это правило действует и для launchers, и
для `svc.py`, и для скриптов восстановления.

## Восстановление

- Панель мертва → кнопка «Сброс» в sidepanel или
  `python sandbox/reload_panel.py --port <CDP>`.
- Агент мертв → ярлык **jewai** на рабочем столе или
  `launchers/boot-all.ps1`.
- Чат потерял вкладки → `python sandbox/reload_chat.py --port <CDP>`.
