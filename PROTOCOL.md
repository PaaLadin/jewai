# Протокол команд

Модель в чате DeepSeek пишет блоки-команды. Расширение Chrome ловит
их в DOM, отправляет локальному агенту, получает результат и
вставляет в чат ответ. Цикл замкнут.

## Формат блока

Блок состоит из открывающей строки, заголовков, опционального тела
и закрывающей строки.

Открывающая строка: три решётки, слово `BEGIN`, три решётки —
на отдельной строке. Обозначим её `[open]`.

Закрывающая строка: три решётки, слово `END`, три решётки — на
отдельной строке. Обозначим её `[close]`.

Разделитель тела (только для операций `write` и `run`): три
решётки, слово `CONTENT`, три решётки. Обозначим его `[split]`.

### Пример read

    [open]
    id: AAAA0001
    op: read
    path: sandbox/file.py
    [close]

### Пример write

    [open]
    id: AAAA0002
    op: write
    path: sandbox/x.py
    [split]
    import sys
    print("hi")
    [close]

## Поля

- `id` — 4 заглавные латинские буквы + 4 цифры. Монотонно вверх.
  Никогда не переиспользовать. Переполнение `AAAA9999` → `AAAB0001`.
- `op` — одна из операций: `write`, `read`, `list`, `mkdir`,
  `delete`, `hash`, `run`, `sandbox`.
- `path` — путь относительно корня установки. Абсолютные пути вне
  корня отклоняются (`safe_path`).
- Тело — только для `write` и `run`, отделяется `[split]`.

## Отчёт

Ответ агента приходит блоком `[AGENT REPORT]` с полями:

- `id` — id исходной команды;
- `op` — операция;
- `OK` или `FAIL`;
- `path` — путь (для файловых операций);
- `bytes` / `sha256` (для чтения/записи);
- `content` / `stdout` / `stderr` (для чтения и запуска);
- `next_id` — следующий свободный id. Продолжать с него.

## Критично: буквальные маркеры в теле

Если в теле записываемого файла содержится буквальная открывающая
строка (три решётки + BEGIN + три решётки), парсер обрежет блок
на ней. Это ловилось на практике.

Решения:

- В документе писать маркеры словами или использовать плейсхолдеры
  вида `[open] / [split] / [close]`.
- В коде собирать маркеры динамически: `H = "#" * 3;
  MB = H + "BEGIN" + H;`.
- В JS-регекспе — не писать их буквально, строить из частей.

## Правило «качели»

Цикл работы: **команда → результат → анализ → следующая команда**.

- Если команда не отправлена — внешний мир не изменился.
- Если результата нет — нельзя делать вид, что он получен.
- Не надо выстраивать длинные фиктивные цепочки «сейчас отправлю,
  вероятно, придёт, тогда я...». Одна команда — один шаг.

## Лимит длины

Рендер чата подрезает длинные code-блоки (порог примерно 5–7 КБ).
Если файл больше — разбивать на 2–3 блока `write` подряд либо
писать через append-скрипт.

## Cooldown и склейка

- Cooldown между командами — 5 секунд.
- Окно склейки (coalesce) — 2.5 секунды: несколько блоков,
  написанных подряд, уходят одним пакетом.
- Silence-timer — 180 секунд: если за это время не отправлено
  ничего, панель напоминает о себе (механизм ALIVE).
  Настраивается в панели v4 (поле «ALIVE порог (сек)»).
