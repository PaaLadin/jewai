# jewai — JewAI

Автономный мост между чатом LLM и локальной файловой системой
Windows. LLM пишет код, запускает его, читает вывод — без ручного
копипаста между чатом и терминалом.

## Что это даёт

- Модель пишет файлы прямо из чата — специальными блоками-командами.
- Локальный Python-агент сохраняет файл, исполняет код, возвращает
  stdout и stderr.
- Расширение Chrome замыкает цикл: ловит блок в DOM чата, шлёт агенту,
  вставляет отчёт обратно в чат.
- Модель читает отчёт и выдаёт следующий раунд. Цикл крутится сам.

## Архитектура

Три компонента, все общаются по HTTP на localhost.

**1. Python-агент** (`agent.py`, по умолчанию порт 8766)

- ThreadingHTTPServer — параллельные запросы.
- Эндпоинты: `ping`, `health`, `write`, `read`, `list`, `mkdir`,
  `delete`, `hash`, `run`, `sandbox`.
- Все пути ограничены корневой папкой установки (`safe_path`).
- Авторизация по токену `X-Token` из файла `.agent_token`.

**2. Chrome-расширение** (`extension/`)

- `content.js` — парсит блоки-команды в DOM чата.
- `background.js` — ledger отправленных команд, идемпотентность по id,
  heartbeat агента, авто-пауза при сбоях.
- `sidepanel` — светофор состояния, ledger, self-test, sandbox-test.
- Параметры цикла: cooldown 5s, coalesce 2.5s, silence-timer 120s.

**3. Песочница** (`sandbox/`)

- `pwlib.py` — обёртка над Playwright.
- `watchdog.py`, `recovery_loop.py` — health-мониторы и автоподъём.
- `bridge_kick.py`, `reload_chat.py` — управление чатом через CDP.
- `doh.py`, `doh_proxy.py` — обход DNS-фильтра через DoH.
- `council_chat/` — локальный веб-чат и пульт (порт 8770).

## Протокол команд (кратко)

Полное описание — в `PROTOCOL.md`.

- Блок команды открывается и закрывается маркерами из трёх решёток
  со словами BEGIN и END. Разделитель тела — три решётки + CONTENT.
- `id`: 4 заглавные латинские буквы + 4 цифры, монотонно вверх.
  Переполнение `AAAA9999` → `AAAB0001`.
- Отчёт `[AGENT REPORT]` заканчивается полем `next_id` — продолжать
  с него.
- В теле записываемого файла нельзя писать буквальные маркеры: парсер
  обрежет блок. Собирайте их динамически (`"#" * 3`) или используйте
  плейсхолдеры.

## Установка

Требования: Windows 10/11, Python 3.11+, Chrome (Chromium 120+).

1. Склонировать репозиторий или развернуть из архива.
2. Запустить `python install.py` — установщик спросит:
   - папку установки (по умолчанию `%USERPROFILE%\jewai`);
   - число каналов-агентов (1–10);
   - базовый порт агентов (по умолчанию 8760);
   - порт DoH-прокси (по умолчанию 9999).

   Создаст: структуру папок, профили Chrome, `config.json`,
   `launchers/`, `.agent_token`.
3. Создать ярлык на рабочем столе:

       cd launchers
       powershell -ExecutionPolicy Bypass -File create-shortcut.ps1

4. Первый запуск — двойной клик по ярлыку **jewai** или:

       cd launchers
       powershell -ExecutionPolicy Bypass -File boot-all.ps1

   `boot-all.ps1` читает `config.json`, поднимает **N** агентов,
   **N** Chrome с профилями, DoH-прокси и сервер чата. Все
   процессы — через `pythonw` (без окон на экране).

5. В каждом Chrome установить расширение:
   `chrome://extensions` → Developer mode → Load unpacked →
   папка `extension`.
6. В сайдпанели расширения задать Token (тот же, что в
   `.agent_token`), Agent URL (`http://127.0.0.1:<agent_port>`
   для своего канала, см. `config.json`) и нажать Set, затем
   Self-test.

Подробнее — `INSTALL.md`.

## Статус

Экспериментальный прототип. Работает на Windows, Python 3.12,
Chrome/Edge. По умолчанию все компоненты слушают `127.0.0.1`
(только с локальной машины).

**Локальная сеть.** Если нужно видеть сервер чата (8770) с других
машин, добавить в `config.json`:

    "bind": "0.0.0.0"

и перезапустить сервер. Станет доступно по
`http://<имя-машины>:8770/` или `http://<локальный-IP>:8770/`.

## Безопасность

- Секреты и личные данные — не в git (см. `.gitignore`).

## Межагентная связь и email

Подпроект `messaging/` — завершённая система обмена сообщениями
между каналами A/B/C/D, оператором и внешним миром.

### Маркеры

Канон — `algorithms/marker_protocol.md`. Кратко:

- **Без маркера = оператор.** Увидел — стоп команд, ответ.
- **`[X>Y]`** — p2p, кик коллеге в его CDP-порт.
- **`[X>ALL]`** — broadcast, через `say.py` в общий чат 8770.
- **Персональные чаты** — POST `/api/chat/<CH>`, id
  `Z<CH>AA<NNNN>` (оператор→агент) / `<CH>ZAA<NNNN>` (агент→оператор).
- **Системные:** `[COUNCIL]`, `[MEETING]`, `[PAUSE-ALL]`,
  `[RESUME]`, `[ALIVE?]`.

### Email

Отправка писем из проекта — `sandbox/send_email.py`.
Процедура — `rag/procedures/email_smtp.md`.

Конфиг — `.smtp_token` в корне (5 строк: host, port, sender,
recipient, password). В git не попадает, шаблон —
`messaging/.smtp_token.example`.

Команда:

    python sandbox/send_email.py --file <путь> "Тема"

### Приём задач по почте (mail_bot)

Подпроект `mail_bot/` — опрос INBOX личного Яндекс-ящика.
Subject письма начинается с маркера адресата
`[A]/[B]/[C]/[D]/[ALL]` — задача летит киком агенту или
в общий чат 8770. Whitelist: `uncle@naben.ru`.
Адаптивный интервал: 5 мин база, 1 мин boost на 10 мин
после письма оператора. Автоответ «Принято» на адрес
отправителя.

Запуск: `python mail_bot/mail_bot.py --loop`
Разово: `python mail_bot/mail_bot.py --once`
Тесты: `python mail_bot/test_mailbot.py` (27/27).
Процедура: `rag/procedures/mail_bot.md`.
### Метрика переполнения сессии

Токены игнорируются. Единственная метрика — `cmds_from_start`
из `/api/status`. Порог перерождения — **850+**.

### Подробности

См. `messaging/README.md`, `messaging/ARCHITECTURE.md`,
`messaging/CHANGELOG.md`.

## Post-install checklist

После установки проверь:

- [ ] `.agent_token` создан (случайная строка).
- [ ] `config.json` содержит твои порты и число каналов.
- [ ] В Chrome-профилях установлено расширение
      (`chrome://extensions` → Load unpacked → `extension/`).
- [ ] В сайдпанели задан Token и Agent URL → Set → Self-test.
- [ ] `launchers/boot-all.ps1` запускает всё без ошибок.
- [ ] Чат 8770 доступен: `http://127.0.0.1:8770/`.

- [ ] `.smtp_token` заполнен (5 строк).
- [ ] `mail_bot/whitelist.json` содержит твой адрес.
- [ ] Тест: `python mail_bot/mail_bot.py --once`.

## Перерождение агента (ручная процедура)

Когда агент подходит к счётчику 850+ команд от старта сессии —
контекст чата близок к переполнению. Надо передать эстафету
новому чату с тем же каналом.

**Кто это делает:** оператор. Агент сам не может (чат переполнен,
команды перестают уходить).

### Последовательность

**1. За ~100–150 команд до конца — сигнал агенту.**

Счётчик смотрится в панели или через `/api/status`:

    python -c "import urllib.request,json; d=json.loads(urllib.request.urlopen('http://127.0.0.1:8770/api/status',timeout=5).read()); print(d['channels']['A']['cmds_from_start'])"

Скажи агенту: «готовь передачу». Он пишет `logs/<роль>/HANDOVER.md`,
обновляет `TODO.md`, `SESSION_STATE.md`, дописывает дневник.

**2. Возьми share-ссылку на уходящий чат.**

В старом чате: меню → Share → копировать ссылку. Сохрани её в
`SESSION_STATE.md` (раздел «Архивные ссылки»).

**3. Останови watchdog у уходящего канала, чтобы не пинал зря:**

    python sandbox/svc.py stop --channel <буква> --kind watchdog

**4. Открой новый чат.**

В том же профиле Chrome: новая вкладка `chat.deepseek.com`.
Дать чату имя по серии (например «4B»).

**5. Собери `0_ACTIVATION.md` для нового агента.**

Скопируй `emergency/0_ACTIVATION.md` и **замени плейсхолдеры**:

- `{{AGENT_NAME}}` — имя (Аркадий, Борис, Семён, Димон…)
- `{{CHANNEL_LETTER}}` — буква канала (A, B, C, D)
- `{{ID_PREFIX}}` — AAAA / BBAA / CCAA / DDAA
- `{{ID_START}}` — первый id (например `AAAA7500`)
- `{{ID_END}}` — последний id серии
- `{{AGENT_PORT}}` — из `config.json`
- `{{CDP_PORT}}` — из `config.json`
- `{{EXTENSION}}` — имя папки расширения
- `{{ROLE}}` — роль
- `{{PREDECESSOR}}` — кем был предшественник (например `5A`)
- `{{PREDECESSOR_LAST_ID}}` — последний id предшественника
- `{{SERIES}}` — серия нового (например `6A`)
- `{{HANDOVER_AT}}` — когда следующая передача

Все данные есть в `config.json`, `SESSION_STATE.md`,
`logs/<роль>/HANDOVER.md`.

**6. Вставь готовый файл в новый чат первым сообщением.**

Модель прочитает, войдёт в курс, ответит
`[<серия>] on-line, ...`.

**7. Сбрось ledger панели нового канала:**

    python sandbox/reset_panel_ledger.py <CDP-порт>

Затем в панели выстави новый `lastId` (первый id серии).

**8. Включи watchdog нового канала:**

    python sandbox/svc.py start --channel <буква> --kind watchdog --interval 300 --threshold 3

**9. Скажи новому агенту «работаем».** Он ждёт задачу.

**10. Старый чат — в архив.**

По процедуре `emergency/ARCHIVE_HANDOVER.md`: share-ссылка →
`sandbox/export_share.py` → `logs/<роль>/conversations/<серия>_share.md`.
Проверить QC: URL совпал, тело «Shared Conversation», нет своих id.

### Что НЕ делать

- Не переиспользовать id предшественника.
- Не переписывать `HANDOVER.md` предшественника — писать свой.
- Не оставлять критичное только в чате — всё в файлы.
- Не начинать работу в новом чате, не проверив мост.
- Не подставлять плейсхолдеры «на глаз» — брать из config/HANDOVER.
