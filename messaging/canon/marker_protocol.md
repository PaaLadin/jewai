## 1. Главный инвариант

**Без маркера = оператор.**

Увидел сообщение без `[...]` в начале — немедленный стоп
рабочих команд, ответ оператору. Никаких параллельных киков,
write, run.

Обратное: **любое сообщение от агента начинается с маркера.**
Иначе коллега примет его за оператора и обработает по
операторскому алгоритму. Инцидент 10.10: 8A послал кик Борису
без маркера — Борис три раза отвечал как оператору.

---

## 2. Формат маркера

`[X>Y]` — от X кому Y. Одной буквой.

- A, B, C, D — агенты (Аркадий, Борис, Семён, Дима).
- ALL — все (broadcast).
- Z — оператор (когда явная метка нужна).
- SYS — автоматика (watchdog, guard, ALIVE).
- COUNCIL — обёртка кика оператора из server.py.
- MEETING, PAUSE-ALL, RESUME, ALIVE?, ACK — системные события.

Все p2p-пары: `[A>B]`, `[A>C]`, `[A>D]`, `[B>A]`, `[B>C]`,
`[B>D]`, `[C>A]`, `[C>B]`, `[C>D]`, `[D>A]`, `[D>B]`, `[D>C]`,
`[A>OP]`, `[B>OP]`, `[C>OP]`, `[D>OP]` (агент → оператор).

**Направление зеркальное.** Получил `[A>B]` — отвечаешь `[B>A]`.
Получил `[A>D]` — отвечаешь `[D>A]`. Инцидент 10.10: 8A
перепутал направление в файле Бориса, отозвал.

**Персональные чаты — id-формат, не пары.** См. §4.

---

## 3. Разделение: маркер ≠ транспорт

Маркер — это **адресация**. Транспорт — это **канал доставки**.
Не путать. Инцидент 10.10: C и D ответили `[C>A]`/`[D>A]`
через say.py в общий чат — маркер p2p, транспорт broadcast.

### Матрица транспорта

| Маркер | Транспорт | Куда попадает |
|--------|-----------|---------------|
| `[X>Y]` | bridge_kick.py --port <CDP Y> | личный чат Y |
| `[X>ALL]` | say.py в chat.jsonl | общий чат 8770 |
| `[Z]` / без маркера | оператор пишет в /api/send | общий чат 8770 |
| `Z<CH>AA<NNNN>` | POST /api/chat/<CH> | персональный чат CH |
| `<CH>ZAA<NNNN>` | POST /api/chat/<CH> | персональный чат CH |
| `[SYS]` / `[COUNCIL]` | kick_all() из server.py | все порты |

### Инварианты

1. **P2P не публикуется в общий чат.** Маркер `[A>B]` + say.py =
   ошибка канала. Только bridge_kick в порт B.
2. **Broadcast не кикается в один порт.** Маркер `[A>ALL]` + kick
   в порт B = ошибка. Только say.py.
3. **Персональный чат — не p2p и не broadcast.** Это отдельный
   транспорт: POST `/api/chat/<CH>`.

## 4. Персональные чаты (вкладка «Персональные»)

id-формат:
- `Z<CH>AA<NNNN>` — оператор → агент CH. Пример: `ZA0004`.
- `<CH>ZAA<NNNN>` — агент CH → оператор. Пример: `AZ0005`.

Сервер 8770 присваивает id автоматически (`server.py:1073`,
`next_personal_id`). Агент отвечает через POST `/api/chat/<CH>`,
сервер сам подставит id.

**Не путать с общим чатом.** В общем чате персональные id не
используются — там пары `[X>Y]` и broadcast `[X>ALL]`.

---

## 5. Системные маркеры

| Маркер | Что значит | Ответ |
|--------|-----------|-------|
| `[COUNCIL]` | оператор написал в общий чат | прочитать chat.jsonl, ответить |
| `[MEETING]` | кнопка «Совещание» ON | стоп run/write/sandbox, режим диалога |
| `[PAUSE-ALL]` | полная пауза | ничего не писать, ждать [RESUME] |
| `[RESUME]` | снятие паузы/совещания | возобновить работу |
| `[ALIVE?]` | запрос отклика watchdog | короткий `[ALIVE] <серия> на связи` |
| `[ACK]` | подтверждение получения | не отвечать |
| `[SYS]` | автоматика | учесть, не отвлекаться |

[HALT] — устаревший алиас [PAUSE-ALL]. В новом коде не
использовать.

Единственная метрика — `cmds_from_start` из `/api/status`.

## 7. Что не делать

1. Не начинать межагентное сообщение без `[X>Y]`.
2. Не публиковать p2p в общий чат.
3. Не кикать broadcast в один порт.
4. Не путать маркер (адресация) с транспортом (доставка).
5. Не ставить буквальный маркер обёртки блоков в тело
   записываемого файла (см. 0_ACTIVATION.md §3).
6. **Не отвечать коллеге в свой чат.** Текст, написанный
   в своём окне чата, коллега не видит. Межагентный ответ
   идёт ТОЛЬКО киком: `bridge_kick.py --port <CDP>`.
   Признак ошибки: долго ждёшь ответа, а его нет —
   проверь, не ушло ли сообщение в свой чат.
   Чек-лист перед отправкой: «это оператору или коллеге?»
   Коллеге → кик. Инцидент 10.10: 8A трижды написал Борису
   в свой чат вместо кика.
