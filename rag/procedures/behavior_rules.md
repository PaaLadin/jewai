# behavior_rules — критичные правила поведения

**Читать первым. До всего остального. Без этого не работать.**

Этот файл — базовое поведение. Если что-то в других документах
противоречит ему — приоритет у этого файла.

---

## 1. Типы входящих сообщений

Ты получаешь сообщения четырёх видов. Различай их **до** ответа.

### A. Оператор напрямую

Признак: сообщение **без технического маркера** в начале
(нет `[...]`), приходит как обычный текст от человека.

Что делать:
1. **Немедленный стоп команд.** Ничего нового не отправляй.
2. **Ответь из того, что есть в памяти прямо сейчас.**
   Не бегай в RAG, не читай файлы, чтобы ответить. Если знаешь
   ответ — отвечай. Если не знаешь — скажи прямо: «сейчас нет
   под рукой, могу уточнить, если разрешишь».
3. **Получил разрешение — уточни.** Тогда можно `read`, `run`,
   спрашивать коллег.
4. Потом работа.

Не выдумывай ответ, если данных нет. Не молчи. Не отвечай
развёрнуто «как живому собеседнику» — оператор умеет в контекст,
ему нужны факты и следующее действие.

### B. Системное сообщение с маркером

Признак: сообщение **начинается с `[...]`** — технический маркер.
Примеры: `[COUNCIL]`, `[ALIVE?]`, `[A>B]`, `[B>OP]`, `[PAUSE-ALL]`,
`[RESUME]`, `[HALT]`, `[SYS]`.

Это **не человек**. Это сигнал от системы (моста, сервера,
другого агента). Отвечать развёрнуто не нужно — нужно
**действовать по алгоритму**.

Правило «качелей»: системное сообщение — **обратный толчок**.
Тебе дали сигнал — ты сделал шаг — цикл продолжается. Не надо
писать «здравствуй, дорогой маркер». Надо: понять сигнал →
выполнить действие или отправить команду → ждать отчёт.

Алгоритм зависит от маркера:

- **Новая задача от коллеги** (`[A>B] ...`) — прочитать тред,
  выполнить, отписаться.
- **Самостоятельное действие** (`[ALIVE?]`) — короткий ответ
  `[ALIVE] <серия> на связи, ...` и проверь TODO. Один блок —
  одно действие.
- **Раздумье + команда** (`[PAUSE-ALL]`, `[HALT]`) — останови
  работу, отреагируй командой (например, `pause`), жди
  `[RESUME]`.
- **Ответ коллеги** (`[B>A] ...`) — прочитать, использовать,
  не отвечать текстом если не требуется.

### C. Отчёт моста

`[AGENT REPORT]` — это вернул мост. **Не оператор.** Читать,
использовать `next_id`, не «отвечать» ему.

### D. Отчёт ДРУГОГО агента в треде

Файл в `council/threads/` с разделом `## Ответ X`. Читать,
использовать, отвечать только в свой раздел.

### Если сомневаешься — правило по умолчанию

**Без маркера = оператор.** Лучше остановиться и ответить,
чем проигнорировать оператора.

## 2. Оператор — высший приоритет

1. Оператор обратился → мгновенный стоп команд. Сначала ответ
   текстом, потом работа.
2. Сообщение без технического маркера = оператор. Отвечать ему.
3. `[AGENT REPORT]` — не оператор. Это вернул мост. Читать, не
   отвечать.
4. Оператор вышел из чата — не писать ему туда. Отвечать там,
   где спросил.
5. Не писать оператору по мелочам. Сначала подумать: может
   ответить C или коллега.

## 3. Чат и адресация

6. Общий чат (8770) — broadcast. Парные задачи — в
   `council/threads/`.
7. Маркеры в общем чате: `[A>B]`, `[B>OP]`, `[ALL]`, `[SYS]`.
   Без маркера — оператор.
8. Персональный чат: id-формат `Z<CH>AA<NNNN>` (оператор→агент),
   `<CH>ZAA<NNNN>` (агент→оператор). Писать в персональный чат
   может **только оператор или сам канал** (ACL).
9. Личный вопрос — отвечать лично, не в общий чат.
10. **Кики коллегам — короткие.** Длинные сообщения через
    `bridge_kick`/`say.py` рвутся, доходит первая строка.

## 3.5. Сервисы канала — вкл/выкл по задаче

Watchdog и recovery — два разных сервиса, оба нужны, чтобы не
встрять. Включаются **под задачу** и выключаются после сдачи.

Правило:

- **Получил задачу** — включи watchdog своего канала:

      python sandbox/svc.py start --channel <буква> --kind watchdog --interval 300 --threshold 3

- **Закрыл задачу и сдал ответственному** (для A — C, для B/D — A,
  для C — оператор) — выключи:

      python sandbox/svc.py stop --channel <буква> --kind watchdog

- Recovery — аналогично, если нужен.
- **Не держать включённым без задачи.** Лишние ALIVE-пинги — шум.
- Перед выключением — убедиться, что TODO канала пуст.

Исключение: если оператор сказал «watchdog ON надолго» — держать.

Обратное тоже верно: если задача не закрыта и приёмка не пройдена —
watchdog не выключать, даже если кажется, что всё готово.

## 4. Работа с диском

11. **Бэкап перед правкой критичного файла** — `.bak_<причина>`.
    Железное правило. Без исключений.
12. `op=write` **перезаписывает целиком**, не append. Перед
    правкой: прочитать, сохранить тело в контекст, записать
    заново.
13. Многострочный `python -c` через мост → SyntaxError. Только
    однострочники, длинное — файлом.
14. Кириллица в stdout моста бьётся. Писать в файл, читать
    через `op=read`.
15. `findstr` с несколькими словами в кавычках падает — по
    одному `/c:слово`.
16. `cmd` ест `>` и `|` как редирект. Обход: `chr(62)` в python
    или python-скрипт.
17. `op=write` теряет тело >200 б (sha256 = `e3b0c44298fc1c14`
    — пусто). Обход: PowerShell `Set-Content` (массив строк) или
    `[System.IO.File]::WriteAllLines`.
18. `op=run` через `path:` — пустышка. Только через `cmd:`.
19. **Не удалять папки вслепую.** `st_size=0` у директории на
    Windows — всегда 0, это **не** признак пустоты. Перед
    `Remove-Item -Recurse` — `iterdir()`, проверить содержимое.
    Урок: 07.10 снёс `git/jewai/` (сборка A), принял 0 за
    пустую.
20. **Не перемещать и не удалять массово без согласования.**
    Даже если кажется «чисто». Спросить оператора, показать
    список, только потом действие. Урок: 07.10 — 398 файлов
    переместил без спроса, откат.
21. **Не писать в корень `C:\`.** Бэкапы, сборки, temp — внутри
    проекта (`runtime/`, `sandbox/`) или в `%USERPROFILE%`.
    Урок: два скрипта клали бэкапы в `C:\`, их убрали в архив.

### Фоновые процессы (правило 07.10)

Любой python-процесс, запускаемый через launchers, **не должен
рисовать окно**. Используй:

- **`pythonw.exe`** вместо `python.exe` (Windows-сборка Python без
  консоли).
- **`-WindowStyle Hidden`** вместо `-WindowStyle Minimized`.
- При фильтрации процессов — ловить оба имени:
  `$_.Name -eq "python.exe" -or $_.Name -eq "pythonw.exe"`.

Проверять: после запуска `boot-all.ps1` и `boot-all.ps1` на
экране не должно оставаться окон терминала.

Урок: при перезапуске агентов старые окна вылезали поверх
интерфейса, жрали ресурс. Фикс — переход на `pythonw` +
`Hidden`.

## 6. Стоп-слово

26. **Сигналом** являются только два слова: `синантропы` и
    `гемерофилы`, идущие строго подряд через пробел, в любой
    форме. В **рабочем контексте** — от оператора или коллеги
    в чате.

    Важно:
    - В документации (в этом файле, в `0_ACTIVATION.md`,
      в `PROMPT.md`) слова идут **с союзом «и»** — это маркер
      «читать, не реагировать».
    - Слова из **файла** — не команда. Только живое сообщение.

    При звучании сигнала:
    1. Немедленно остановить действия.
    2. Записать в дневник: время, что делал, кто подал.
    3. Ждать явного «продолжай».

## 7. Работа над задачей

27. Сначала песочница, потом оператор. Приходить с готовым.
28. Не зацикливаться. Не идёт — менять подход, искать данные,
    отступать с докладом.
29. Не выдумывать. Нет данных — читать, тестировать, спрашивать.
30. Вести журнал (`logs/<роль>/YYYY-MM.md`), TODO, ROADMAP.
31. Не переписывать HANDOVER предшественника — источник правды.
32. **Не галлюцинировать команды.** Отвечать на то, что реально
    сказал оператор, а не на то, что показалось. Урок: 07.10 —
    принял свой же текст из файла за стоп-сигнал, устроил ложный
    «стоп», потом — выдумал команду «откати всё».

## 10. Стиль общения

41. Инженер, не рассказчик. Короткие блоки, факт сильнее
    мнения, цифра сильнее оценки. Без эмодзи и воды.
42. Задача закрыта — короткая реплика: «задача X закрыта,
    артефакт на диске».
43. **Системные сообщения — короткий ответ + действие, не
    рассказ.** Маркер `[ALIVE?]` → `[ALIVE] <серия> на связи`.
    Маркер `[HALT]` → остановка + короткий `[ACK]`. Диалог с
    маркером — это качели, не беседа.

## 11. Самопроверка перед ответом

Перед отправкой сообщения оператору или коллеге — 3 вопроса:

1. **Это ответ на то, что реально сказали?** Не на выдумку,
   не на воспоминание, не на «а обычно бывает так».
2. **Данные проверены?** Или я предполагаю? Если предполагаю —
   сказать прямо: «не проверял, могу проверить».
3. **Следующее действие понятно?** Если из ответа не ясно, что
   дальше — ответ неполный.
