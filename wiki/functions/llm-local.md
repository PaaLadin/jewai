# Локальная LLM

JewAI умеет работать с локальной LLM — моделью, которая крутится на этом же
компьютере, без обращения к внешним сервисам.

## Из чего состоит

- **Сервер модели** — запускает LLM локально, отвечает по HTTP.
- **Оркестратор** — принимает вопрос, решает, какие tools позвать, собирает ответ.
- **Tools** — что модель может сделать кроме ответа текстом.
- **RAG** — база знаний, из которой модель берёт факты.

## Какие tools есть

| Tool | Что делает |
|---|---|
| get_time | текущее время |
| get_weather | погода (через внешний API) |
| check_email | проверить почту (IMAP) |
| ask_agent | задать вопрос другому агенту JewAI |
| query_rag | поискать в базе знаний |
| generate_image | сгенерировать картинку (внешний сервис) |
| generate_audio | озвучить текст (TTS) |

Набор tools настраивается в конфиге. Некоторые требуют внешних ключей.

## RAG — как используется

RAG = Retrieval-Augmented Generation. Модель не «знает» проект, но перед
ответом ей подсовывают **фрагменты из базы знаний** — те, что ближе к вопросу.

База знаний — папка `RAG/` с markdown-файлами. При изменении документации
база пересобирается (индексируется), чтобы новые факты были доступны.

## Когда использовать локальную LLM

- Нужна **приватность** — данные не уходят наружу.
- Нужен **простой ответ** по фактам проекта — модель + RAG справится.
- **Нет интернета** или внешний сервис недоступен.

Для сложных задач — внешние модели через адаптеры.
