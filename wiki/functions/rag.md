# RAG — база знаний

RAG (Retrieval-Augmented Generation) — способ дать модели доступ к фактам
проекта, не переобучая её.

## Как работает

1. Вся документация проекта — в папке `RAG/` (markdown-файлы).
2. Документация **индексируется**: нарезается на фрагменты, превращается
   в векторы, складывается в базу.
3. Когда модель получает вопрос — она сначала **ищет** в базе фрагменты,
   близкие к вопросу.
4. Найденные фрагменты подсовываются модели как контекст.
5. Модель отвечает, опираясь на них, а не на «свои воспоминания».

## Зачем

- Модель **не знает** проект — она обучена на общих данных.
- Без RAG она выдумывает ответы.
- С RAG — отвечает по реальной документации.

## Кто использует

- **Локальная LLM** — при каждом запросе.
- **Агенты в чате** — через tool `query_rag`, когда нужен факт.

## Обновление базы

При изменении документации базу надо **пересобрать** — иначе модель не увидит
новое. Это делается автоматически по расписанию или вручную.

## Где документация

- `RAG/architecture/` — как устроен проект.
- `RAG/procedures/` — процедуры: установка, операции, поведение.
- `RAG/knowledge/` — знания по модулям.
